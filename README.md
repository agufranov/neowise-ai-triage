# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

Если порт 3000 недоступен, пример запуска в PowerShell:

```powershell
$env:PORT = '43187'
node server.mjs
```

В этом случае откройте http://127.0.0.1:43187.

## Тесты

```sh
node --test triage.test.mjs
```

Зависимостей для тестов нет. Проверки запускают настоящий HTTP-сервер на свободном
локальном порту: невалидный ввод, три темы, все пять сценариев сбоя имитатора,
лимит ожидания и проверка структуры ответа AI. Отдельно проверяется обработчик
страницы: очистка предыдущего черновика при сбое, сетевые ошибки, повторная попытка,
пустой ввод и защита от повторной отправки. Эти проверки используют простые
заменители элементов страницы, а не полноценный браузер.

## Что реализовано

Результат AI проверяется в `server.mjs` перед формированием ответа API: тема должна
быть `delivery`, `pricing` или `other`, черновик — непустой строкой. Внешние поля
не копируются в ответ. Ошибка модели, неверный JSON или структура и ожидание дольше
300 мс дают `manual_review` с `topic: null` и `draft: null`. Таймер отменяет запрос
через `AbortSignal`; ограничение действует и для провайдера, который игнорирует
отмену. Имитатор `mock-ai.mjs` не изменён.

Страница показывает тему по-русски и черновик как текст. Предыдущий результат
очищается при каждой новой отправке, при сбое появляется инструкция разобрать
заявку вручную. Сетевая ошибка, неверный ответ API и ожидание сети более 5 секунд
также переводят интерфейс к ручному разбору. Повторная отправка доступна после
завершения запроса; менеджер проверяет черновик и сам решает, что отправлять.

Для ручной проверки: получите черновик для «Уточните стоимость», затем по очереди
отправьте каждую метку сбоя из списка ниже. Убедитесь, что старый черновик исчезает,
появляется сообщение о ручном разборе, а следующая обычная заявка снова работает.

Польза для менеджера: меньше времени на подготовку первого ответа; измерять можно
медианным временем от открытия заявки до проверенного менеджером черновика.

При реализации использован AI — Codex. Автоматические проверки перечислены выше;
результат тестов и ограничения проверки интерфейса указаны в описании PR.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Что прислать в бота

- Ссылку на pull request и SHA проверяемого коммита. Можно использовать свой учебный репозиторий. Сохраните начальный код первым коммитом, затем откройте PR из отдельной ветки.
- Короткую инструкцию запуска и прогона теста. В описании PR ответьте, где проверяется результат AI, что происходит при сбое, какой AI вы использовали и что проверили самостоятельно. Если работали без AI, укажите это.
- Одну фразу о том, какую пользу задача даёт менеджеру и как её можно измерить.

После сдачи бот может задать один-два коротких вопроса по вашему коду. Используйте учебные данные. Если не уложились по времени, отметьте незавершённые части в PR.
